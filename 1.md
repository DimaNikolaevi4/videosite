

# 🚪 Иммерсивный веб-сайт: Путеводитель по созданию
**Погружение через видео, анимацию и интерактивный диалог**

## 📌 Концепция
Пользователь попадает на сайт и переживает последовательность сцен:

1. Видео открывающейся двери.
2. Девушка с планшетом, планшет раскрывается на весь экран.
3. Форма регистрации на планшете.
4. Планшет исчезает, камера движется к столику.
5. Вид на собеседника за столиком, общение через текст/голос с помощью ИИ.

Всё это работает в браузере как одностраничное приложение (SPA) без перезагрузок.

## 🎯 Три уровня реализации (от простого к сложному)
Выбери уровень, исходя из навыков команды, бюджета и сроков.

| Уровень | Описание | Плюсы | Минусы | Рекомендации |
|---------|----------|-------|--------|--------------|
| **1. Видео-фон + CSS/HTML** | Каждая сцена – отдельное видео. Планшет и диалоги — HTML-элементы поверх. | Быстрая разработка, отлично на мобильных | Меньше интерактивности, стыки видео могут быть заметны | Для MVP или быстрого теста |
| **2. 2.5D с Three.js и спрайтами** | 3D-сцена из плоскостей, на которые проецируются видео. Камера управляется кодом. | Полный контроль над движением, плавные переходы, умеренная сложность | Нужно знание Three.js | **Рекомендованный старт** |
| **3. Полный 3D с анимированными персонажами** | Реалистичные модели, липсинг, интерактивное окружение. | Максимальная иммерсивность | Высокая стоимость, нагрузка на устройство | Когда бюджет и время не ограничены |

Данный гайд написан для **Уровня 2**, но большинство шагов применимы и к другим вариантам.

## 🧱 Технологический стек (рекомендуемый)

| Слой | Инструменты |
|------|-------------|
| **Фронтенд-фреймворк** | React (или Vue 3) |
| **3D-движок** | Three.js + GLTFLoader |
| **Анимации** | GSAP (GreenSock) — синхронизация DOM и Three.js |
| **Видео на текстурах** | VideoTexture (Three.js) |
| **Искусственный интеллект** | OpenAI API (gpt-4o-mini) / аналог |
| **Голос** | Web Speech API (распознавание + синтез) или ElevenLabs |
| **Бэкенд (прокси)** | Node.js + Express, либо Serverless Functions (Vercel/Netlify) |
| **Хранение пользователей** | Firebase Auth + Firestore или Supabase |
| **Деплой** | Vercel / Netlify |

## 🗺️ Дорожная карта (Roadmap) по этапам

### Этап 0: Подготовка и прототип
1. **Создать HTML-страницу** с последовательным показом трёх `<video>` фонов:
   - `door.mp4` (открытие двери)
   - `girl_with_tablet.mp4` (девушка держит планшет)
   - `fly_to_table.mp4` (пролёт камеры к столику)
   - `person_at_table.mp4` (собеседник за столиком, idle-петля)
2. Реализовать анимацию «планшет на весь экран» поверх второго видео — простой `<div>` с `transform: scale` через GSAP.
3. Добавить заглушку формы регистрации.
4. Проверить плавность переходов и корректность на мобильных.

### Этап 1: Перенос на Three.js (если выбран уровень 2/3)
1. Инициализировать сцену Three.js, камеру, рендерер.
2. Создать плоскости (`PlaneGeometry`) для каждого видеофона и наложить `VideoTexture`.
3. Позиционировать плоскости в виртуальном пространстве так, чтобы камера видела их как экраны.
4. Анимировать планшет как 3D-объект (плоскость с формой регистрации через CSS3DRenderer или текстуру с canvas).
5. Реализовать плавный полёт камеры от позиции «девушка» к позиции «столик» (GSAP).

### Этап 2: Регистрация и работа с пользователями
1. Настроить Firebase Auth (email/пароль или OAuth).
2. Встроить форму регистрации внутрь планшета.
3. При успешной регистрации запускать обратную анимацию схлопывания планшета и переход к сцене столика.

### Этап 3: Диалоговый интерфейс и ИИ
1. Разработать компонент чата: поле ввода, история сообщений, облачка.
2. Создать серверный прокси (Express/Serverless) для запросов к OpenAI.
3. Написать системный промпт персонажа (администратор, стиль общения, цели).
4. Интегрировать прокси с фронтендом.
5. (Опционально) Добавить голосовой ввод через `SpeechRecognition` и чтение ответов через `SpeechSynthesis`.

### Этап 4: Оптимизация и продакшн
1. Сжать все видео в WebM (VP9) с низким битрейтом.
2. Настроить предзагрузку ресурсов и прелоадер.
3. Протестировать на различных устройствах, добавить адаптивный fallback (на мобильных — только видеофоны без 3D).
4. Настроить CI/CD деплой на Vercel/Netlify.
5. Подключить фоновую музыку и звуковые эффекты через Web Audio API.

## 💡 Полезные советы напоследок
- **Видеоконтент — самая ресурсоёмкая часть.** Если не можешь снять реальное видео, используй анимацию в Blender или After Effects.
- **Для общения с ИИ начни с простого текстового чата.** Голос добавь позже, когда основа заработает стабильно.
- **Делай частые коммиты и создавай резервные копии.** Проект быстро обрастает медиафайлами, а потерять их обидно.
- **Не бойся смешивать техники.** Даже в 2.5D-сцене можно использовать обычный HTML для формы регистрации — это упростит вёрстку.
